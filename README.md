## 과제 7 업데이트

Supabase Auth 공식 라이브러리 2.117.3으로 실제 이메일 확인 후 앱 전용 비밀번호 로그인을 연결합니다. 서버 세션은 무작위 256비트 값의 SHA-256만 저장하고 Secure/HttpOnly 쿠키를 발급합니다. 만료·로그아웃·앱에서 비밀번호 변경 후 기존 세션을 차단합니다. 모든 계획과 하위 자료는 서버에서 확인한 본인 계정에 제한합니다. 기존 자료는 설정된 본인 이메일 인증 후 이관됩니다.

피드백은 본인 목록과 관리자 개선 보관함으로 나눕니다. 반복 의견 묶음과 우선순위, 개선안 초안은 로컬 규칙으로 생성합니다. 글씨·대비·버튼 간격 관련 의견은 본인 화면에 자동 적용하며 끄기·초기화와 변경 이력을 제공합니다. 외부 AI 분석과 자동 코드 변경·배포는 아직 연결되지 않았습니다. 비밀번호 원문·세션·토큰은 접속 기록에 저장하지 않습니다.

현재 Supabase 기본 메일 서비스는 프로젝트 구성원 이메일에만 발송합니다. 일반 이메일 가입에는 별도 SMTP 연결이 필요합니다. 메일 발송 연결 전에는 일반 주소의 가입을 완료할 수 없습니다. 계정 관리에서 앱 자료 전체 내보내기·삭제를 지원하며, 다이어리 계정 삭제 후 본인 앱 이메일·자료·세션은 지워지고 다시 로그인할 수 없습니다. Supabase 인증 계정은 유지된다고 안내합니다.

검증: `node scripts/test-auth.mjs` (실제 API 경로와 메모리 SQLite, 인증 공급자 응답은 모의), `node scripts/test-duration.mjs`, `npx tsc --noEmit`. 운영 이메일 가입, 실제 두 계정 및 실제 5일 사용 기록은 별도로 확인해야 합니다.

제출 준비 문서: docs/task07/authentication.md(6항목), docs/task07/submission/ (조건 대조·확인 4줄·AI/나 3줄·모의 요청/응답 근거). test-auth는 19개 검사이며 운영 메일·두 계정·hash/salt·5일 사용의 완료 증거가 아닙니다. 다이어리 계정 삭제 후 앱 이메일·세션·본인 자료는 지워지고 다시 로그인할 수 없습니다. Supabase 인증 계정은 남으므로 공급자 계정까지 삭제한 것으로 표시하지 않습니다.

‘실제 5일 사용 기록’ 영역에서 첫날 규칙과 실제 작업 구간을 달·주·시간·분·초 중 선택해 초 정밀도로 입력합니다. 서버가 서울 날짜를 기록하므로 과거 날짜 입력·당일 중복·6번째 기록을 거절합니다. 두 기록 뒤 시작 규칙을 한 번 바꾸고 이유와 근거를 저장하며, 5일 뒤 전후 합계·평균 손계산을 대조합니다. 미기록 날짜는 제외, 720분 초과 이상값은 표기 후 포함, 합계·평균·전후 차이는 원래 초 합계로 계산 후 분 단위 소수 둘째 자리 반올림, 주 시작은 월요일입니다. 실사용 지표도 분으로 저장하며 소수 분으로 초 정밀도를 유지합니다.

## 비밀번호 찾기
로그인 화면에서 가입한 이메일로 재설정 링크를 요청한다. 같은 브라우저에서 30분 안에 링크를 열어 8~128자 새 비밀번호를 설정한다. 서버 PKCE 확인과 일회용 흐름으로 재설정하며 기존 앱 세션을 모두 무효화한다. 기존 비밀번호 원문은 제공하거나 기록하지 않는다. 일반 메일 발송에는 SMTP 연결이 필요하며 실제 메일 수신 검증은 아직 대기 중이다. Supabase 복귀 허용 주소에 `/auth/recovery`를 포함한다.

## 재설정 안정성 및 스크롤 효과
링크 코드는 입력 화면 진입 시 한 번 교환하고, 10분 만료 AES-GCM 암호화 HttpOnly 쿠키로 새로고침을 이어간다. 같은/약한 비밀번호는 같은 화면에서 수정해 재시도할 수 있으며 만료·중복·변조 요청은 차단한다. 운영 환경의 RECOVERY_SESSION_KEY는 Sites 비밀값으로 설정한다. 비밀번호와 토큰은 공개 소스와 관리자 로그에 넣지 않는다. 배경은 스크롤에 따라 최대24px 이동하고 1.5도 기울어지며 입력 중·동작 줄이기 환경에서는 멈춘다. 인증 경로 모의 검증23개 통과. 실제 이메일 발송·링크 확인은 운영 브라우저에서 별도로 확인한다.

화면 이동 안정성: 재설정 화면의 로그인 복귀와 새 링크 요청은 일반 페이지 이동을 사용한다. 인증 코드 제거 시 기존 브라우저 이동 상태를 보존한다. 로그인/회원가입/비밀번호 찾기 전환 클릭을 확인했고 네트워크 대기가 무한히 버튼을 잠그지 않도록 15초 제한을 적용한다.

## 앱 구성 · 아이디와 멤버 커뮤니티
사이드바에서 계획·실행·돌아보기·5일 기록·커뮤니티·피드백·설정을 각각 연다. 기존에 한 화면에 쌓였던 계정/기록/피드백/설정 패널은 해당 메뉴에만 표시한다. 설정에서 이메일 인증된 본인 계정의 로그인 아이디(소문자·숫자·밑줄3~20자), 표시 이름과 소개를 등록하며 아이디/이메일 모두 기존 Supabase 비밀번호 인증을 사용한다. 아이디는 중복 등록할 수 없고 비밀번호 원문은 기록하지 않는다.
커뮤니티는 로그인된 회원만 접근한다. 직접 게시한 글과 댓글, 선택한 본인 계획의 제목·기간·성공기준 요약만 멤버에게 공유한다. 이메일·개인 할 일·실행기록은 공유하지 않는다. 원래 계획의 후속 수정은 이미 공유한 요약에 자동 반영되지 않는다. 작성자는 글/댓글을 철회할 수 있고 관리자는 삭제 조정할 수 있다. 프로필/작성글/댓글은 본인 전체 내보내기와 계정 자료 삭제에 포함된다. 별도 개인 메시지·실시간 채팅·푸시 알림은 구현되지 않았다.
